# Current-affairs links

Published events: **0**. Published current-affairs-linked questions: **0**. No live discovery worker or scheduled refresh is configured. Do not fabricate a news connection to fill this area.

For an audit on2026-10-01, the rolling twelve-month review window begins2025-10-01. Compute this from the actual review date; do not keep this example as a fixed application boundary.

## Record contract

`event_id`, `event_date`, `discovered_at`, `last_reviewed_at`, summary, credible source URLs and source IDs, historical topic, microconcept IDs, relevance reason, canonical past-PYQ links, suitable model IDs, evidence level, review status, expiry/next-review date and reviewer.

Publication needs a verified dated event and an explicit syllabus-linked historical fact. Official anniversaries, memorials, resolutions, reports or court decisions may provide recall context, but do not establish an exam prediction. Event facts and underlying history must be checked independently. Sensitive legal developments require the actual authoritative document and current status.

Evidence levels: A strong revision signal, B important, C watchlist, D low evidence. Store reasons, not an invented numeric probability. No historical recurrence claim until the linked PYQs are authenticated. Relevance decays with age; a recurring anniversary gets a new reviewed event record rather than silently reviving an expired claim.

Refresh design: discover → register sources → validate date and content → link ontology → review relevance → propose only supported question models → validate → publish. The future refresh must update data without a frontend rebuild. Generated output keeps its generated classification and explicit current-affairs link.
